## 二、计算模块的设计与实现

程序分为入口和计算模块。`main.py` 只负责调用；`paper_checker.py` 提供四个接口：文本规范化、重复率计算、文件输入输出和命令行错误处理。这样计算函数不依赖文件，便于单元测试。

```mermaid
flowchart LR
    A[三个命令行路径] --> B[读取原文和抄袭版]
    B --> C[NFKC 与大小写规范化]
    C --> D[移除空白标点符号]
    D --> E[一元组与二元组 Counter]
    E --> F[加权 Dice 重复率]
    F --> G[写入两位小数]
```

核心算法使用字符 n-gram 多重集。对于多重集 A、B：

```text
Dice(A, B) = 2 × |A ∩ B| / (|A| + |B|)
```

一元组反映总体字符重合，二元组反映相邻语序，最终按 20% 和 80% 加权。相较依赖词典的分词算法，它不需要第三方模型；相较纯集合算法，它会保留片段出现次数；段落移动时，段落内部的二元组仍可匹配。

```python
left_counts = Counter(left)
right_counts = Counter(right)
overlap = sum((left_counts & right_counts).values())
return 2.0 * overlap / (len(left) + len(right))
```

## 三、性能分析与改进

第一个版本用列表逐项查找并删除匹配片段，`cProfile` 显示 `_naive_dice` 和 `list.remove` 占用绝大多数时间。最终版本改用 `Counter` 交集，保持算法公式和输出不变，把最坏时间复杂度从 O(n²) 降为 O(n)。

| 实现 | 15,400 字符耗时 | 结果 |
| --- | ---: | ---: |
| 优化前 | 1.109023 秒 | 0.810514 |
| 优化后 | 0.146865 秒 | 0.810514 |

分析场景提速 7.55 倍。1 MiB 输入正常计算耗时 0.890186 秒，诊断峰值内存 117.150 MiB，满足5秒和2048 MB限制。

## 五、异常处理

| 场景 | 行为 | 对应测试 |
| --- | --- | --- |
| 参数不是三个 | 输出用法，退出码2 | `test_main_rejects_wrong_argument_count` |
| 输入不存在 | 输出错误，退出码1 | `test_main_reports_missing_input_without_traceback` |
| UTF-8、GB18030均无法解码 | 输出编码错误，退出码1 | `test_main_reports_invalid_encoding` |
| 输出路径不可写 | 输出写入错误，退出码1 | `test_main_reports_unwritable_output_location` |
| 输出路径与输入相同 | 先读完两个输入再覆盖 | `test_output_may_overwrite_an_input_after_both_are_read` |

所有预期异常都转成单行中文错误信息，不显示 traceback；程序运行时不访问网络，也不扫描或修改指定路径之外的文件。

## 六、总结

这次实现中最明显的改进是用性能分析数据定位朴素多重集匹配的二次复杂度，并在不改变相似度语义的前提下替换为线性计数器算法。后续如果评分方给出统一标注语料，可以进一步用标注数据调整一元组与二元组的权重，而不是凭直觉修改。
